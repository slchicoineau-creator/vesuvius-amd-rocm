## The downstream "lasagna fit" on a crop (and why the chain needs a stand-in axis)
The organizers' seed fit (`fit.py`, shipped configs) starts from cylinder shells grown around the scroll's umbilicus (`cyl_init_tool.py` with `configs/init_cyl.json`), then fits a patch with `configs/init.json` (`init-mode shell-dir-crop`). Both read the manifest's `umbilicus_json`. There is no 0841 umbilicus at this crop (z 9572 is below the team's clicked range 12800-16200) and the whole-scroll chain is not run on a 256^3 crop. So:
- **Stand-in axis (rule, frozen):** a vertical line at distance R from the crop centre (4500, 3850, 9700) along the unoriented xy normal of the sheets, oriented so its x component is >= 0. The normal is the principal axis of the nx/ny structure tensor over the central 128^3 base-voxel block of the **REF** predictions, weights grad_mag x (|n_xy| > 0.5) (`axis.py`; it never reads FAST or STOCK). The same axis file is used by all three arms. On REF at R = 900 it gives n_xy = (0.954, 0.300), eigenvalue ratio 77 (coherent, near-planar parallel sheets), axis at (5358.7, 4119.6). The axis is a geometric device for the shell tool, not a claim about the scroll.
- **Stage 0 ladder for R (plumbing only, REF seed 1):** R = 900, then 600, then 1500; the first rung whose REF seed-1 chain passes the check below is frozen for every arm and every seed (`R_used.txt`). The check is plumbing: `cyl_init_tool.py` and `fit.py` exit 0, the exported tifxyz has >= 90 % finite valid vertices, >= 90 % of valid vertices inside the crop +-64 vx, area >= 20,000 vx^2 (`check0.py`). Distances between arms are not looked at to choose a rung. All three rungs failing = **INCONCLUSIVE ("tool cannot run here")**, no pass or fail is claimed; the failure class (env / compile / data / diverged / other) goes into `stage0.json` and the diagnosed root cause into the RESULT.
- Allowed engineering ladder, in this order, only if a command fails to run (not for any result): `--cuda-gridsample 0` (if the dense sampling kernel fails on gfx1201), `--sparse-prefetch-backend python-zarr` (if tensorstore fails). Any other change needs an amendment before outputs.
- Component checks already done on CPU before this prereg (no GPU touched): the 5 JIT kernels of the streaming loader (`sparse_prefetch_chunks`, `sparse_grid_sample_3d_u8`, `..._diff`, `grid_sample_3d_u8`, `..._diff`) and the libigl extension `cyl_sdf_volume_ext` all BUILD with hipify on ROCm 7.2.2 (gfx1201), 20-30 s each. That they RUN correctly is not yet known; it is what Stage 0 tests. The axis direction rule was first looked at on the GATE16c STOCK output (exploration), then frozen as written above on REF.
- Commands (frozen): shell `cyl_init_tool.py configs/init_cyl.json --input <manifest> --out-dir <shells> --device cuda --z-range 9572 9828 --shell-count 1`; fit `fit.py configs/init.json --input=<manifest> --init-shell-dir <shells> --seed X Y Z --model-w 200 --model-h 200 --depth 1 --device cuda --out-dir <dir>` (shipped `configs/init.json` unchanged: 1000 + 500 steps, mesh-step 50). `ROCBLAS_USE_HIPBLASLT=0` (fp32). villa_main d63d3e968 + `lasagna_rocm.patch` (sha256 e970674e8786324a5770cc6c79d2fb045a789adb81db9dafb1b99fa10c0af9a2). One shell per arm (from that arm's predictions).

## Seeds
The lasagna fit has **no random number generator** (checked: no `manual_seed`/`rng` in `fit.py`, `optimizer.py`, `model.py`, `cli_*.py`); `--seed` is a point. So "3 fit seeds per arm" are three seed points (same three for every arm), which is the only seed-like input of the shipped fit:
- s1 = the crop centre (4500, 3850, 9700); s2 = s1 + 16 vx along the in-plane sheet tangent (xy, from `axis_info.json`, rounded); s3 = s1 + 16 vx in z.
- All three lie within one sheet's patch (patch 200 x 200 vx). Run-to-run GPU non-determinism is inside each fit; it is not separated out, only measured as part of the same-arm spread.
- Fits: 3 arms x 3 seeds = 9 fits (REF s1 doubles as the Stage 0 fit).

## Metric (frozen)
- `[internal reference removed]` (sha256 f6a7d355b49e78d9409341d253ffb78b535c38aca993b210a33b8fb539409985): its own `load()` and `surface_match()`, i.e. the **point-to-surface** distance. Turn agreement does **not apply** (one winding, depth 1, no turn numbers): stated, not skipped silently.
- Each exported tifxyz (`winding_0000.tifxyz`) is first densified by bilinear interpolation to a vertex pitch <= 6 vx (a 50 vx fit grid would make fit_compare's 15 vx tangential limit meaningless; applied identically to all fits; a quad with any invalid corner stays invalid).
- Pair distance d(A, B) = mean of the two directional medians (A to B, B to A) of the point-to-surface distance (vx). Also reported: share <= 4 vx, p90.
- Scorer: `score.py` (sha256 2b2ab4131da59bb84e5da754413478ed91cce2d3d7535bafef33f973885cbbfd), tested before this prereg on synthetic planes only (a 1 vx shift gives 1.02, a 3 vx shift 2.99).

## Pooling and bar (stated explicitly)
- **Bar B = the largest REF-vs-REF seed-to-seed distance** (3 pairs: s1-s2, s1-s3, s2-s3 of REF), the registered rule's "largest same-arm seed-to-seed distance of the reference".
- **Decision statistic M = the median over the 9 cross pairs REF_si vs FAST_sj** (i, j in 1..3, including the 3 same-seed pairs).
- **PASS iff M <= B.** FAIL otherwise. INCONCLUSIVE if Stage 0 cannot run, or fewer than 9 + 3 fits finish.
- **Reported, not deciding:** the MAX over the 9 cross pairs, and whether it would also be <= B (the strict reading that failed the spiral cross-device check); FAST-vs-FAST and STOCK-vs-STOCK spreads; STOCK-vs-REF (9 pairs, median and max); FAST-vs-STOCK; all individual pair distances; the absolute size in vx and um (9.366 um/vx) and against the sheet scale (band width median 96 um = about 10 vx). If B is below 0.5 vx the bar is tighter than the fit's own grid noise: the registered verdict stands and is reported with that remark.
- Not claimed whatever the outcome: other crops/scrolls/models/scales; the scroll-scale chain (real umbilicus, many shells, `init_snap_surf_self_full`, which left its seed on 0841 in LASAGNA-FIT-9); that either surface is the right sheet; `overlap 64`.

## What each outcome changes
- **PASS:** on this crop, through this chain, surfaces fitted from FAST predictions are within the REF fits' own seed-to-seed spread of the REF surfaces. That answers Sebastien's condition 2 for this crop; it is one crop and one chain, said so. Package numbers may rest on the fast path only to that extent (his call).
- **FAIL:** acc32_bias is not shown to give the same fitted surface; GATE16c/SCOPE2 stay as prediction-level results; numbers going into a submission are re-run on stock. The disagreement is characterised (size, where, direction) in the RESULT; no second mode is tried under this prereg.
- **INCONCLUSIVE:** reported with the diagnosed cause; no pass claimed.
- STOCK-vs-REF is read as a scale only: if STOCK and FAST are both inside B the test cannot separate them (said plainly); it does not change the verdict.
